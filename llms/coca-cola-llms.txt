## API surfaces

- [Coca-Cola internal API platform (MuleSoft Anypoint)](https://www.mulesoft.com/webinars/api/evaluation-to-implementation-coca-cola-company-journey): API-led connectivity across bottling, marketing, ecommerce and supply chain, governed by a Center for Enablement. Internal and partner only; no public contract.
- [TCCC Soft Bottler Agent Hub](https://github.com/The-Coca-Cola-Company/bottler-soft-infra-poc): a multi-tenant hub-spoke agent architecture on Azure API Management. Bottlers deploy a spoke into their own Azure tenant and register it with the TCCC hub. Base URL is templated per deployment: https://tccc-soft-prod-apim-{uniqueid}.azure-api.net. Auth is an Ocp-Apim-Subscription-Key issued by TCCC. Documented operations: POST /api/agents/register (register a bottler agent with capabilities, endpoint, region) and GET /api/health on the spoke Function App (x-functions-key). Partner-gated; not callable by a third party.
- Retired: Coca-Cola Enterprises Product API and Location API, developer.cokecce.com / api.cokecce.com (Mashery). See lifecycle/coca-cola-lifecycle.yml.

## Agent posture

The Coca-Cola Company builds with agents but publishes nothing agents can call.
Its own bottler repository declares Model Context Protocol servers (Cosmos DB,
Blob Storage, Service Bus), Semantic Kernel plugins and memory, AutoGen
agent-to-agent orchestration, and Azure AI Foundry model routing — all of it
provisioned into a bottler's private Azure subscription behind the TCCC APIM
hub. There is no hosted MCP endpoint and no installable package. See
mcp/coca-cola-mcp.yml.
